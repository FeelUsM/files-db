Идея рабочая. Вот как я бы её собрал.

**Слепок**: плоский словарь `путь → запись`:
`{type, dev, ino, size, mtime_ns, ctime_ns, btime_ns, uid, gid, mode, nlink, link_target}`.
- Время создания на Linux берётся через `statx` (`st_ctime` это время смены метаданных, не создание). На некоторых ФС birth time нет.
- Для переименований добавь `nlink` и для симлинков `link_target`.
- Хеш содержимого не нужен в слепке. При желании считай его лениво, только для изменившихся файлов.

**Обратимый diff**: по каждому пути одна запись одного из видов:
- `added: {new}`
- `removed: {old}`
- `changed: {поле: [old, new]}`
- `moved: {from, to, changed: {...}}`

Чтобы получить старый слепок из нового, нужно применить diff в обратную сторону. Для `added` удаляем путь, для `removed` возвращаем `old`, для `changed` ставим `old`, для `moved` переносим обратно.

**Перемещения**: ищем пары «удалён путь A, появился путь B» с одинаковым `(dev, ino)`. Номер inode может переиспользоваться после удаления, поэтому дополнительно сверяй `btime`, а если его нет, то `size` и `mtime`. При переименовании папки все её потомки окажутся moved. Лучше схлопнуть это в одну запись `dir_moved {from, to}` с подстановкой префикса.

**Теги и запросы**:
- Теги папки действуют на всё её поддерево. Набор тегов пути это объединение тегов самого пути и всех его предков.
- Запрос с набором тегов T берёт записи diff, где старый путь или новый путь подходит под T.
- Для перемещений теги проверяются отдельно для старого и нового пути. Файл, переехавший из тегированной папки в нетегированную, для T считается «ушедшим».
- Изменение размера равно (сумма размеров нового состояния внутри T) минус (сумма размеров старого состояния внутри T). Перенос внутри T даёт 0.
- Для пустого T подходит всё.

Для сотен тысяч файлов json-слепок станет тяжёлым. На этом этапе он удобен, а потом тот же формат можно положить в sqlite.

Два уточнения, чтобы не угадывать:
1. Набор тегов в запросе трактуем как **AND** (путь содержит все теги) или как **OR**?
2. Тебе нужен код на Python (табы для отступов) или пока достаточно спецификации формата?

**3. Diff**

```json
{
	"format": 1,
	"root": "/home/u",
	"from": "2026-10-01T15:00:00Z",
	"to": "2026-10-02T09:00:00Z",
	"changes": [
		{"op": "add", "path": "dir/N.txt", "new": {"type": "f", "size": 50, "...": "..."}},
		{"op": "remove", "path": "dir/B/x.txt", "old": {"type": "f", "size": 70, "...": "..."}},
		{"op": "change", "path": "dir/C.txt", "set": {"size": [100, 150], "mtime_ns": [1790000000, 1790009999]}},
		{"op": "move", "from": "dir/D.txt", "to": "dir/A/D.txt", "set": {"ctime_ns": [1, 2]}}
	]
}
```

- Список упорядочен по пути.
- Для отката каждая операция инвертируется: `add` и `remove` меняются местами, в `change` и `move` пары `[old, new]` разворачиваются, а у `move` меняются `from` и `to`.
- Откат применяется атомарно: сначала все удаления и исходные позиции перемещений, затем все вставки. Так обмен A↔B не ломается.
- Перемещённая папка записывается явно для каждого потомка. Схлопывать это для показа можно, а в хранимом формате ломает обратимость.

**4. Результат запроса** (не файл, а вывод)

```json
{
	"query": {"mode": "and", "tags": ["tag", "photos"]},
	"added": ["dir/N.txt"],
	"removed": ["dir/B/x.txt"],
	"changed": ["dir/C.txt"],
	"moved": [{"from": "dir/D.txt", "to": "dir/A/D.txt"}],
	"size": {"added_bytes": 50, "removed_bytes": 0, "delta": 50}
}
```

- Запись из diff подходит под запрос, если под набор тегов попадает старый или новый путь.
- Вклад в `delta` равен размеру на новом пути (если тот в наборе) минус размер на старом (если тот в наборе). Файл, который ушёл из набора, считается как удалённый, а пришедший в набор как добавленный.
- Пустой набор значит «всё», в режимах AND и OR одинаково.
- Для AND нужны все теги пути, для OR хотя бы один.
- Текущий файл тегов применяется и к старым, и к новым путям.

Всё вынес в `./.changes/`. Ниже обновлённые форматы.

**1. TAGS.txt**

```
// настройки
@root	/home/u
@exclude	.cache/
@exclude	dir/B/tmp/	// можно и в конце строки

// теги
dir/	# tag
	A/
	B/	# no_tag

```

- **Комментарии:** `//` начинает комментарий в любом месте строки. Имя файла не может содержать `/`, поэтому `//` не встретится внутри пути.
- **Пути:** все пути, включая `@exclude`, относительны `@root`.
- **Исключения:** `.changes/` всегда исключается автоматически.

**2. Слепок (дерево)**

```json
{
	"format": 2,
	"root": "/home/u",
	"taken_at": "2026-10-01T15:00:00+03:00",
	"exclude": [".cache/", "dir/B/tmp/"],
	"tree": {
		"type": "d", "dev": 2049, "uid": 1000, "gid": 1000, "ino": 2, "size": 4096, "mtime": 1790000000000000000, "ctime": 1790000000000000000, "btime": 1780000000000000000, "mode": "0755",
		"c": {
			"dir": {
				"type": "d", "ino": 131, "size": 4096, "mtime": 1790000000000000000, "ctime": 1790000000000000000, "btime": 1780000000000000000, "mode": "0755",
				"c": {
					"C.txt": {"type": "f", "ino": 140, "size": 100, "mtime": 1790000000000000000, "ctime": 1790000000000000000, "btime": null, "mode": "0644"},
					"lnk": {"type": "l", "ino": 141, "target": "C.txt", "...": "..."}
				}
			}
		}
	}
}
```

- Имя узла служит ключом в `c`, поэтому пути не повторяются.
- Поля `dev`, `uid`, `gid` наследуются от родителя, если не указаны.
- Времена в наносекундах.
- Исключённых поддеревьев в дереве нет.
- В слепке хранится список `exclude`, с которым он снят.

**3. Diff**

```json
{
	"format": 2,
	"root": "/home/u",
	"from": {"taken_at": "2026-10-01T15:00:00+03:00", "exclude": [".cache/"]},
	"to": {"taken_at": "2026-10-02T09:00:00+03:00", "exclude": [".cache/", "dir/B/tmp/"]},
	"changes": [
		{"op": "add", "path": "dir/N.txt", "new": {"type": "f", "size": 50, "...": "..."}},
		{"op": "add_scan", "path": "data/x.txt", "new": {"...": "..."}},
		{"op": "remove_scan", "path": "dir/B/tmp/y.txt", "old": {"...": "..."}}
	]
}
```

- Заголовок хранит `taken_at` и `exclude` обоих слепков, иначе откат не восстановит слепок целиком.
- Тип операции определяет положение пути. Если путь исключён в `from`, но не в `to`, это `add_scan`. Если путь исключён в `to`, но не в `from`, это `remove_scan`. Во всех остальных случаях это обычные `add` и `remove`.
- Файл, перенесённый в исключённую папку, считается обычным `remove`.

**4. Раскладка**

```
.changes/
	TAGS.txt
	scan_20261001-150000.json
	scan_20261003-120000.json
	diff_20261001-150000_20261002-090000.json
	diff_20261002-090000_20261003-120000.json
```

- Время в именах локальное. По именам файлов `changes.py` узнаёт список моментов, не открывая файлы.
- **chkan.py:** первый запуск пишет только первый слепок. Каждый следующий пишет новый слепок и diff. Затем он проверяет, что `reverse(новый слепок, diff)` равен предыдущему слепку, и удаляет предыдущий, если он не первый. Остаются первый слепок, последний слепок и все diff.
- **Прогресс-бар:** общий объём заранее неизвестен, поэтому за 100% берётся число объектов предыдущего скана. При первом скане будет только счётчик.

**5. changes.py**

```
changes.py [from [to]] [and|or] теги...
changes.py - 2026-10-02 tag      // "-" значит «момент не указан», нужен чтобы задать только to
```

- **Форматы момента:** `09:30` или `09:30:15` (сегодня), `2026-10-01` (время 00:00:00), `2026-10-01T09:30` (секунды 00; с пробелом нужны кавычки).
- **Выбор момента:** берётся ближайший не позже указанного. Если он раньше первого скана, будет ошибка.
- **Значения по умолчанию:** без аргументов берётся последний шаг. Если указан только `from`, то `to` равен последнему моменту. Если указан только `to`, то `from` равен предыдущему моменту.
- **Разбор аргументов:** слова `and` и `or` и всё, что похоже на момент, нельзя использовать как теги.
- **Объединение diff:** результат показывает чистое изменение между двумя моментами. Файл, созданный и удалённый внутри периода, не показывается, как и `add_scan` и `remove_scan`.
- **Теги:** применяется текущий TAGS.txt.

## claude
**Зарезервированные теги и символы**

- `exclude`: объект и его поддерево не сканируются. Снимается тегом `no_exclude`.
- Префикс `no_`: `no_X` снимает тег `X`, поэтому свои теги не могут начинаться с `no_`.
- `(ignore)`: это пометка, а не тег. Скобки в именах тегов запрещены.
- Имена тегов: только буквы, цифры, `_` и `.`, потому что `+` и `-` нужны в ключах групп.
- На будущее зарезервирую `and` и `or`, если вернёмся к changes.py.

**TAGS.txt**

```
// root = папка, в которой лежит .changes/
# logs(ignore)	// только помечает тег
# docs	// ничего не значит

.cache/	# exclude
dir/	# tag
	A/
	B/	# no_tag
	C.txt
	D.txt	# no_tag
var/	# logs
```

- Строка без пути, но с `(ignore)`, только помечает тег.
- Строка с путём и `(ignore)` помечает тег и ещё ставит его на путь.
- Если тег хоть раз помечен `(ignore)`, он игнорируемый везде.

- **Папки-предки:** когда меняется файл, меняется `total` у всех его папок-предков. Они все попадают в diff как `change_d`.

## claude
Спец-теги с `@` и `@run` готовы, 222 теста проходят (один пропущен, как раньше). Я прогнал и твои примеры на временной папке (`sudo` заменил на `echo`): команды выполняются в нужных папках, переменные на месте.

**Спец-теги.** Зарезервированных имён больше нет. Теги `exclude`, `no_x`, `and`, `or` теперь обычные.
- **`@exclude`:** работает как раньше `exclude`.
- **`@no(тег)`:** снимает тег с этого пути и его поддерева. Отменить спец-тег нельзя: `@no(@exclude)` даёт ошибку. Неизвестный `@что-то` тоже ошибка с номером строки.
- **`(ignore)`:** `тег(ignore)` остаётся как был.

**Комментарии.** `//` теперь считается комментарием в начале строки или после пробела. Раньше он резал строку в любом месте, из-за этого `http://...` в команде обрезался бы. Минус: ` // ` с пробелом внутри команды всё же начнёт комментарий. Скобки в тексте комментария на разбор команды не влияют.

**`@run(команда)`.**
- **Разбор:** команда идёт до первой `)  @run(` или, если такой нет, до последней `)` в строке. Поэтому `@run` нужно писать последним в строке: в `@run(echo hi) @no(t)` команда захватит и `@no(t)`.
- **Папка:** в `папка111 # @run(...)` текущая папка команды `папка111`, в `# @run(...)` это root.
- **Исполнение:** все команды выполняются по порядку в самом конце, после строк со счётчиками, через `bash -c`. Перед каждой печатается `папка111 # @run(команда)` или `. # @run(...)`.
- **Переменные:** `CHKAN_TAGS`, `CHKAN_DIFF`, `CHKAN_SCAN` — абсолютные пути.
- **Отмена и ошибки:** при отмене из-за предупреждений или ошибке проверки команды не запускаются.

Что я решил сам:
- **Первый скан:** команды выполняются и на нём, а `CHKAN_DIFF` пустой.
- **Сбой команды:** если команда завершилась с ненулевым кодом или её папки нет, остальные команды всё равно выполняются, а chkan.py возвращает код 3. Скан при этом уже сохранён.
- **Шаблон TAGS.txt:** обновлён под новый синтаксис.
